公众号粘贴实测

逐个点「复制」，粘进公众号后台编辑器，看哪几种图片活了下来。目的是确认编辑器现在的 data URI 方案能不能直接用，还是必须先上图床。

  1. 用 Chrome / Edge 打开本页（Safari 的剪贴板行为不一样）。
  2. 登录公众号后台 → 新建图文 → 光标放进正文。
  3. 点下面某个「复制」，回到后台 ⌘V，记下结果。
  4. 每测一个新建一段空行，别让几个用例混在一起。

用例 1 · data URI 图片

编辑器目前的做法：图片以 <img src="data:image/png;base64,…"> 内嵌。若粘贴后图没了或变成裂图，说明必须上图床。

用例 2 · https 远程图片

图床方案：<img src="https://…">。正常情况下公众号会自动抓取并转存进素材库。

用例 3 · 图文混排（两种图一起）

一次粘贴里同时放 data URI 与 https 图，直接对照哪张留下了。文字的内联样式（字号 / 颜色 / 引用块）也一并检查。

用例 4 · 外部链接

顺带确认外链粘进去之后是什么状态：还是可点的 <a>，还是被剥成纯文字。这决定要不要做「外链转文末脚注」。

判读：用例 1 的图没了 / 裂图 → 必须接图床，复制前把 data URI 换成 https。
用例 1 活着但用例 2 也活着 → 两条路都能走，图床仍更稳（草稿在微信侧长期有效）。
用例 4 的链接变成纯文字或不可点 → 值得做外链转脚注。
